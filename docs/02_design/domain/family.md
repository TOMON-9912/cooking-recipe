## 1. このドメインが存在理由

- **利用者にとっての価値:** 家族の味を、他の家族に漏らさず共有・継承できる
- **守れなければならないこと:** 他家族のデータに触れない。下書きは作者以外に見せない

## 2. スコープ

| 含む | 含まない（他ドキュメントまたは未着手） |
| --- | --- |
| グループの作成、作成者の所属、概要の閲覧 | 脱退、解散、複数家族、強制追加・削除 |
| 宛先指定の招待の発行・一覧・取り消し（オーナー）と、本人の承認による参加（Issue #37） | アプリからのメール送信、参加コード、秘密のトークン、オーナー以外の発行 |
| 1 ユーザー 1 家族。人数の上限 6 人（オーナーを含む） | メンバーの役割分け、オーナーの交代、課金による上限の切り替え UI |
| 公開レシピの閲覧範囲としての家族 | 家族メンバーによるレシピ編集（現状は作者のみ） |

## 3. 用語（このドメインの言葉）

| 用語 | 意味 | 使わない言い方 |
| --- | --- | --- |
| 家族グループ | 共有の単位。1 件の `families` | チーム、ワークスペース |
| オーナー | グループを作った人。名前変更の権限を持つ | 管理者ロール（未導入） |
| メンバー | そのグループに所属している人 | |
| 招待 | オーナーが宛先メールを指定して作る、1 人分の参加許可。期限つき | 招待リンク、招待コード、トークン |
| 案内の URL | オーナーが相手に渡すアプリの URL（`/family`）。秘密は含まない | 招待リンク、共有 URL |
| 承認 | 宛先本人が、自分の操作でその家族のメンバーになること | 追加、登録（他人が入れるように聞こえる） |

## 4. アクターと境界

| アクター | このドメインでの役割 | 備考 |
| --- | --- | --- |
| 未所属ユーザー | グループを 1 つ作れる（ゲストも可）。自分宛ての招待を承認できる（本登録のみ） | 招待・承認だけ本登録関門（ADR 007） |
| オーナー | 招待の発行・一覧・取り消しができる（本登録のみ） | 発行・一覧・取り消しはオーナーだけ（ADR 011） |
| オーナー / メンバー | 同じ家族の公開レシピを読める | 書き込みは現状作者のみ |
| ゲスト | 自分の家族を作れる。招待の発行・承認はできない | 本登録で解除される |

| 相手ドメイン | こちらが期待すること | 相手に任せること |
| --- | --- | --- |
| ユーザー | 認証済みの人が所属する。本人確認は登録時のメール確認を使う | プロフィール表示名、確認メールの送信 |
| レシピ | 公開済みだけ家族に見える | 材料・手順の中身 |

## 5. 中核概念

### 5.1 集約

| 集約 | ルート | 中に含むもの | 集約の外に出さないもの |
| --- | --- | --- | --- |
| 家族グループ | 家族 ID | 所属（メンバー） | レシピ本体（作者経由で共有する） |
| 招待 | 招待 ID | 宛先メール、期限、使用・取り消し | トークン（持たない） |

### 5.2 識別子

| 対象 | 同一性の基準 | 注意 |
| --- | --- | --- |
| 家族グループ | ID | 名前の重複は許容 |
| 所属 | ユーザー ID × 家族 ID | 同一家族への重複参加は不可。1 ユーザー 1 家族は関数内で保証（一意制約は付けない） |
| 招待 | ID | 宛先メールは自然キーにしない |

### 5.3 値として扱うもの

| 概念 | 許容される値・形 | 不正な例 |
| --- | --- | --- |
| 宛先メール | 1 件のメールアドレス。比較・保存は小文字に揃える | 空、複数アドレス、大文字小文字を別人とみなすこと |
| 人数の上限 | オーナーを含む 6 人。定数 1 箇所 | 画面だけ 6、DB は無制限 |

## 6. 不変条件

| ID | 条件 | いつ保証するか | 破れたときの扱い |
| --- | --- | --- | --- |
| INV-01 | 1 ユーザーは高々 1 家族 | 作成時・承認時 | 拒否。`user_id` の一意制約は付けない（ADR 005 の複数家族を残す）。`approve_family_invite` 内で直列化して拒否する |
| INV-02 | 作成者は必ず最初のメンバーになる | 作成時 | 拒否（中途半端な家族は残さない） |
| INV-03 | メンバー操作は自分自身の参加・脱退だけ | 常時 | 拒否（他人の強制追加はしない） |
| INV-04 | 参加できるのは、宛先メールでログインした本人が、有効な招待を承認したときだけ | 承認時 | 拒否（家族 ID や案内 URL だけでは入れない） |
| INV-05 | 招待は 1 人宛て、発行から 1 日以内、未取り消し・未使用のときだけ使える | 承認時 | 拒否 |
| INV-06 | 招待を発行できるのは、その家族のオーナーだけ | 発行時 | 拒否 |
| INV-07 | 招待の一覧と取り消しができるのは、その家族のオーナーだけ | 照会時・取り消し時 | 拒否 |
| INV-08 | 家族の人数（オーナーを含む）は 6 人を超えない | 承認時 | 拒否。上限の値は定数 1 箇所（NFR-07） |
| INV-09 | 同じ家族の同じ宛先に、期限内の未使用招待を重ねて作れない | 発行時（発行用 DB 関数内） | 拒否。取り消すか期限切れのあとなら再発行できる |
| INV-10 | 承認の所属追加と、招待の使用済み化は同時に成立する | 承認時 | どちらかだけ残したらロールバック |

## 7. 状態とライフサイクル

家族グループ自体に状態はない（解散は未着手）。所属しているか、していないかだけ。

招待:

```text
未使用 --承認--> 使用済み
未使用 --取り消し--> 取り消し済み
未使用 --期限到来--> 期限切れ
```

| 状態 | 意味 | その状態で許される操作 | その状態で見える相手 |
| --- | --- | --- | --- |
| 未使用 | 期限内で、まだ使われても取り消されてもいない | 承認、取り消し、一覧 | オーナー（宛先と期限）。宛先本人（家族名だけ） |
| 使用済み | 宛先本人が承認してメンバーになった | なし | オーナーの一覧には出ない |
| 取り消し済み | オーナーが取り消した | なし（承認できない） | オーナーの一覧には出ない |
| 期限切れ | 発行から 1 日を過ぎた | なし（承認できない） | オーナーの一覧には出ない |

禁止遷移: 使用済み・取り消し済み・期限切れからの承認。取り消し済みの再有効化。使用済みの取り消し。期限切れの行を取り消す必要はない。

## 8. 操作

| ID | 操作 | 事前条件 | 事後条件 | 主な失敗 |
| --- | --- | --- | --- | --- |
| OP-01 | 家族を作る | 未所属 | グループと自分の所属がある | 既に所属している |
| OP-02 | 招待を発行する | 家族のオーナー・本登録。同じ宛先の期限内未使用が無い | 1 人分の未使用招待がある。案内 URL は `/family` | オーナーでない、ゲスト、重ね発行 |
| OP-03 | 招待を承認する | 未所属・本登録・メール確認済み・宛先本人・有効な招待・人数 6 未満 | メンバーになり、招待は使用済みになる | 既に所属、ゲスト、未確認、人数上限、使用済み、取り消し済み、期限切れ、宛先違い、未ログイン |
| OP-04 | 招待を取り消す | 家族のオーナー・本登録・対象が未使用 | その招待は承認できない | オーナーでない、ゲスト、使用済み |

| ID | 照会 | 返すもの | 見えてはいけないもの |
| --- | --- | --- | --- |
| Q-01 | 自分の家族概要 | 名前とメンバー | 他家族 |
| Q-02 | オーナーの有効な招待一覧 | 招待 ID、宛先メール、期限 | 取り消し済み・期限切れ・使用済み。他家族の招待 |
| Q-03 | 自分宛ての未使用招待（所属の有無は問わない） | 招待 ID、家族名、期限 | メンバー、レシピ、オーナー名、他人宛ての招待、宛先が登録済みかどうか |

## 9. 権限と可視性

| 対象 | 読む | 作る | 変える | 消す |
| --- | --- | --- | --- | --- |
| 家族グループ | メンバー。承認前の宛先本人は家族名だけ（Q-03） | 未所属ユーザー | オーナーのみ（名前） | 未着手 |
| 所属 | 同じ家族 | 作成時はオーナー本人の直接追加。承認は DB 関数だけ | しない | 自分自身のみ（UI 未着手） |
| 招待 | オーナーは自家族の未使用（宛先と期限）。宛先本人は自分宛てだけ（家族名） | オーナーのみ。宛先の登録有無は調べない | 承認の成立時に使用済み。オーナーが未使用を取り消し済みにする | しない（行は残す。一覧には出さない） |

例外: 発行・取り消し・承認・自分宛て照会は、それぞれの `security definer` 関数だけが行う。ゲストは発行も承認もできない。所属 INSERT と招待の使用済み化は `approve_family_invite` のみ。

## 10. 整合性と同時実行

- **一つの操作で同時に変わらなければならないもの:** 家族行と作成者の所属。承認では所属の追加と招待の使用済み化
- **途中失敗したら残してはいけないもの:** メンバーのいない家族。所属だけ増えた招待、使用済みだけ進んだ招待
- **同時に二人触ったときの方針:** 2 つ目の所属は拒否。同じ招待の同時承認は 1 人だけ。同じ家族への同時承認で 7 人目は拒否。いずれも `approve_family_invite` 内で直列化する（家族行と、承認するユーザー単位のロック）
- **重ね発行:** `create_family_invite` が家族行をロックしてから、期限内未使用の同一宛先を見て拒否する。直 INSERT では作れない

## 11. 失敗の意味

| 失敗 | 利用者に伝えること | リトライしてよいか |
| --- | --- | --- |
| 既に家族がある | 新しい家族は作れない／別の家族には参加できない | いいえ |
| 未ログイン | ログインが必要 | ログイン後に、自分で家族管理へ進む |
| ゲスト | 本登録が必要（発行・承認） | 本登録後 |
| メール未確認 | 確認メールのリンクを開いてから承認する | 確認後 |
| 人数がいっぱい | この家族は人数の上限に達している。オーナーに頼む | いいえ |
| 重ね発行 | 同じ宛先の招待がまだ有効。取り消すか期限切れを待つ | 取り消し後 |
| 自分宛ての招待が期限切れ・取り消し済み・承認済み | その理由と、オーナーに再発行を頼む案内 | いいえ |
| 招待が無い／他人宛て | 理由は区別せず「この招待は使えません」と伝え、オーナーに再発行を頼むよう案内する | いいえ |
| オーナーでない | 招待の発行・一覧・取り消しはできない | いいえ |

自分宛ての失効（FR-10）と、他人の招待の有無（NFR-05）は分ける。後者は「無い」と同じ文にする。

## 12. 永続化してよいこと / してはいけないこと

| 残す | 残さない | 理由 |
| --- | --- | --- |
| 家族名・オーナー・所属 | レシピへの family_id | 共有は作者と所属で判定する（ADR 005） |
| 招待の宛先メール・期限・使用者・取り消し時刻 | 招待用の秘密トークン | 本人確認は `auth.users.email`（`id = auth.uid()`）で足りる（ADR 011）。JWT の email クレームだけに頼らない。トークンを持つことが認可にならない |

宛先メールは本人（オーナーの一覧と、宛先本人）以外に出さない。

## 13. 未決・意図的に後回し

| 項目 | 現状の仮置き | 決めるまで禁止すること |
| --- | --- | --- |
| 複数家族への所属 | 1 ユーザー 1 家族のまま。`user_id` 一意制約は付けない | 複数所属の UI、一意制約の追加 |

案内 URL の行き先は `/family`。ログイン後に自動で戻る処理は作らない（FR-13）。

## 14. 受け入れの目安

- [x] 未所属ユーザーが家族を作ると、自分だけがメンバーになる
- [x] 既に所属しているユーザーは家族を作れない
- [ ] オーナーが、宛先メールを指定して招待を発行できる
- [ ] オーナーが、期限内未使用の招待一覧（宛先、期限）を確かめ、未使用を取り消せる
- [ ] 取り消した招待では承認できない
- [ ] 宛先メールでログインした未所属の本登録ユーザーが、家族管理で招待を確かめ、承認して入れる
- [ ] 既に所属している人も、家族管理で自分宛ての招待（家族名）を確かめられ、承認できない理由が分かる
- [ ] 家族 ID や案内 URL だけでは入れない
- [ ] 使用済み・取り消し済み・期限切れ・宛先違い・ゲスト・既に所属・人数 6 人は承認できない
- [ ] 同じ宛先への、期限内の重ね発行はできない
- [ ] 既存の家族作成がこれまでどおりできる

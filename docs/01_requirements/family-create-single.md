# 家族作成を本人の1件に限る

## 1. 背景・目的

家族は1人につき1件で、作った本人がその家族のオーナーになる、というルールはすでに決まっています。画面から家族を作るときは、このルールどおりに動きます。

一方で、画面を通さない操作では、ログインしていることしか見ていません。そのため、他人をオーナーにした家族や、すでに家族に入っている人の2件目を作れます。作られた家族は、オーナーにされた人の画面に、自分では作っていない家族として現れます。

今回は、画面から作ったときも、画面を通さずに作ろうとしたときも、同じ結果になるようにします。家族に入っていない人は、自分をオーナーとする家族を1件作れます。すでに家族に入っている人の追加の家族と、本人以外をオーナーにした家族は、できあがらないようにします。

招待による参加、脱退、解散、オーナーの交代は、今回変えません。

## 2. 利用者の要求

| ID | 利用者 | 要求 |
| --- | --- | --- |
| R-01 | まだ家族に入っていない人 | 自分の家族を1件作り、その家族のオーナーになりたい |
| R-02 | すでに家族に入っている人 | 自分の知らない家族や、2つ目の家族が増えないようにしたい |
| R-03 | ゲストとして使っている人 | 家族に入っていなければ、これまでどおり自分の家族を1件作りたい |
| R-04 | 招待を受けている人 | 家族の作り方の変更で、招待を承認して参加できなくなるのは避けたい |

## 3. 要件

| ID | 要件 | 応える要求 | 優先度 |
| --- | --- | --- | --- |
| FR-01 | 家族に入っていない人が家族を作ると、その人をオーナーとする家族が1件でき、その人が最初のメンバーになる | R-01 | 必須 |
| FR-02 | すでにいずれかの家族に入っている人が家族を作ろうとすると、新しい家族はできず、いま入っている家族のままである | R-02 | 必須 |
| FR-03 | ログイン中の本人以外をオーナーにして家族を作ろうとすると、その家族はできない | R-02 | 必須 |
| FR-04 | FR-02 と FR-03 は、画面から操作したときも、画面を通さない操作のときも、同じ結果になる | R-02 | 必須 |
| FR-05 | ゲストは、家族に入っていなければ自分の家族を1件作れる。招待の発行と承認は、これまでどおりゲストにはできない | R-03 | 必須 |
| FR-06 | 招待された人が承認して家族に入ること、および既存の招待の発行・一覧・取り消しは、これまでどおりできる | R-04 | 必須 |

## 4. スコープ・制約

### 含める

- 家族に入っていない人が、自分をオーナーとする家族を1件作れること
- すでに家族に入っている人は、新しい家族ができないこと
- 本人以外をオーナーにした家族ができないこと
- 画面を通さない操作でも、上と同じ結果になること
- いまの画面からの家族作成が、これまでどおり完了すること

### 含めない

- 招待の承認の作り直し
- 脱退、家族の解散、オーナーの交代
- 招待の発行・一覧・取り消しの権限の変更
- 家族の人数の上限の変更

## 5. 受け入れ条件

- [ ] 家族に入っていない人が家族を作ると、その人の家族が1件でき、その人がオーナーかつ最初のメンバーになっている
- [ ] すでに家族に入っている人が家族を作ろうとしても、家族は増えない
- [ ] 本人以外をオーナーにした家族はできない
- [ ] 上の2つは、画面を通さない操作でも同じ結果になる
- [ ] ゲストは、家族に入っていなければ自分の家族を1件作れる
- [ ] 招待の承認による参加と、オーナーによる招待の発行・一覧・取り消しは、これまでどおりできる

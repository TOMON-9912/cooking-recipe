# 2026年11月の Node.js セキュリティ更新への追従（要件定義）

| 項目 | 内容 |

| ステータス | 確定 |

## 1. 背景と課題

- 2026-11-11 に、Node.js 22、24、26 向けのセキュリティ更新が出た。修正版は 22.23.5、24.22.3、26.13.1 である。いちばん重いものは、Node.js 自身の HTTP/2 や HTTPS を公開しているサーバが、認証なしの相手から停止したり、他の接続のメモリを読まれたりし得るものである
- このアプリは、2026-10-24 に Node.js 24 の系統へ揃えてある。開発、自動の確認、デプロイは、いずれも 24 の系統を指し、パッチ番号では固定していない
- 2026-11-15 時点の開発機は Node.js 24.22.1 である。11月11日の修正は 24.22.3 以降に入るため、24.22.1 には入っていない
- デプロイ先は、選べるのがメジャー番号だけである。セキュリティのためのパッチはデプロイ先が 24 の系統へ入れる。公開されている対応表には、今日のパッチ番号は載っていない
- アプリの画面やデータの扱い自体は、この更新の原因ではない。開発機の版が、修正より前の 24 のままである

## 2. なぜ作るか

- **目的:** このアプリを、2026-11-11 のセキュリティ更新を含む Node.js 24 で動かせるようにする
- **価値:** 系統は合っているのに、開発機だけ修正前の版のままにしない
- **成功の姿:** 開発時の Node.js は 24.22.3 以降である。自動の確認とデプロイは 24 の系統のままである。レシピや家族の使い方は、これまでと変わらない

## 3. 利用者と要求

| ID | 利用者 | 要求（〜したい。なぜなら〜） |
| --- | --- | --- |
| R-01 | このアプリを開発・公開する人 | 2026-11-11 の修正が入った Node.js で、このアプリを動かしたい。なぜなら、いまの開発機は 24.22.1 で、その修正が入っていないから |
| R-02 | このアプリを開発・公開する人 | 系統の指定は 24 のままにしたい。なぜなら、一つのパッチ番号に固定すると、次の修正のたびに指定を書き換えることになるから |
| R-03 | レシピを書く人、家族で使う人 | これまでどおりレシピや家族の機能を使いたい。なぜなら、実行環境の版を上げることが、使い方の変更になってほしくないから |

## 4. 要件

### 4.1 機能要件

| ID | 要件 | 応える要求 | 優先度 |
| --- | --- | --- | --- |
| FR-01 | このアプリを、2026-11-11 の修正を含む Node.js 24 で起動し、これまでどおり使える | R-01、R-03 | 必須 |

### 4.2 非機能要件・制約

| ID | 要件 | 観点 | 優先度 |
| --- | --- | --- | --- |
| NFR-01 | 開発に使う Node.js は 24.22.3 以降である | セキュリティ | 必須 |
| NFR-02 | 自動の確認とデプロイが指す Node.js は、24 の系統のままである。パッチ番号では固定しない | セキュリティ | 必須 |
| NFR-03 | レシピ、家族、アカウントのできることは、この変更の前と変わらない | 互換性 | 必須 |

## 5. スコープ

| 含める | 含めない |
| --- | --- |
| 開発に使う Node.js を、2026-11-11 の修正を含む 24 にすること | パッチ番号を指定に固定すること |
| 自動の確認とデプロイの指定を、24 の系統のままに保つこと | Node.js 26 への変更 |
| その版での起動と、すでにある確認 | 画面、保存するデータ、アカウントの機能変更 |
| | 本番の再公開と、本番が使っている版の確認 |
| | 設計書の新規作成 |
| | Vitest（モック）、Vitest（実 DB）、e2e の新規作成 |

## 6. 前提・決定済み

| 項目 | 内容 | 出典 |
| --- | --- | --- |
| 系統 | Node.js 24 のままにする。22 にも 26 にも移さない | [Node.js のセキュリティ更新への追従](./node-security-update.md)。2026-10-24 にユーザーが選択 |
| パッチの指定 | リポジトリの指定は 24 の系統のままにし、24.22.3 という番号では固定しない | 2026-11-15 に、このチャットでユーザーがこの方針を要件に残すと依頼 |
| 修正は受け取る | 24.22.1 は 2026-11-11 の修正対象外なので、開発環境の版は上げる | 2026-11-15 に、このチャットでユーザーが版を上げる作業へ進むと依頼 |
| 進め方 | 要件定義のあと、開発環境の版を上げる。設計は作らない | [#58](https://github.com/TOMON-9912/cooking-recipe/issues/58)。2026-11-15 にユーザーが依頼 |
| 確認の範囲 | 実装時の確認は、開発時の版と、すでにある確認が通ることとする。3 種のテストを新たに作ることは、この開発対象に含めない | [#58](https://github.com/TOMON-9912/cooking-recipe/issues/58) |
| 更新の事実 | 2026-11-11 のセキュリティ更新は、Node.js 22.23.5、24.22.3、26.13.1 で提供されている | [Node.js のセキュリティリリース](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases) |
| デプロイ先の版の選び方 | 選べるのはメジャー番号だけである。セキュリティのためのパッチは、デプロイ先が 24 の系統へ入れる。対応表には今日のパッチ番号は載っていない | [Vercel の Node.js の対応バージョン](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions) |
| 本番 | 本番の再公開と、本番が使っている版の確認は、この作業の完了に含めない。開発環境が 24.22.3 以降であれば足りる | 2026-11-15 に、このチャットでユーザーが選択 |

## 7. 受け入れ条件

- [ ] 開発に使う Node.js が 24.22.3 以降である
- [ ] 自動の確認とデプロイの Node.js の指定が、24 の系統のままである。一つのパッチ番号に固定していない
- [ ] その版でアプリが起動し、すでにある確認が通る
- [ ] レシピ、家族、アカウントのできることは、この変更の前と変わらない

## 8. 未決・リスク

| 項目 | 現状 | 決めるまで実装に持ち込まないこと |
| --- | --- | --- |
| 既存の道具が 24.22.3 以降で動かない | 2026-10-24 の確認では、既存のテストと lint は 24.22.1 で動いた。24.22.3 以降では未確認 | 動かない道具が出たら、系統を変えるか、その道具だけを直すかを、その時点で人間が決める |

## 9. 設計への申し送り

この開発対象では設計を作らない。保存するデータ、権限、画面は増えない。決めることは、開発に使う Node.js を 24.22.3 以降にすることと、系統の指定をパッチ番号で固定しないことだけである。

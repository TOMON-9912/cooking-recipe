# Node.js のセキュリティ更新への追従（要件定義）

| ステータス | 草案 |

## 1. 背景と課題

- 2026-10-21 に、Node.js 22、24、26 向けのセキュリティ更新が出た。いちばん重いものは、攻撃者が作った圧縮データを展開すると、メモリの露出や任意のコード実行につながり得るものである
- このアプリが CI とデプロイで指定しているのは Node.js 20 である。Node.js 20 はサポートが終わっており、この更新は入らない
- デプロイ先の案内でも、Node.js 20 のプロジェクトは 22 か 24 に上げて、出し直す必要があるとされている
- アプリの画面やデータの扱い自体は、この更新の原因ではない。指定している実行環境が、更新を受け取れない系統のままである

## 2. なぜ作るか

- **目的:** このアプリを、2026-10-21 のセキュリティ更新を受け取れる Node.js で動かせるようにする
- **価値:** サポートが終わった実行環境のまま、公開や開発を続けなくてよくなる
- **成功の姿:** 開発時も、自動の確認時も、デプロイ時も、同じ Node.js 24 の系統を使っている。レシピや家族の使い方は、これまでと変わらない

## 3. 利用者と要求

| ID | 利用者 | 要求（〜したい。なぜなら〜） |
| --- | --- | --- |
| R-01 | このアプリを開発・公開する人 | セキュリティ更新が入る Node.js で、このアプリを動かしたい。なぜなら、サポートが終わった 20 のままでは、今回の更新を受け取れないから |
| R-02 | このアプリを開発・公開する人 | 開発、自動の確認、デプロイで、使う Node.js が食い違わないようにしたい。なぜなら、場所によって古い系統が残ると、更新したことにならないから |
| R-03 | レシピを書く人、家族で使う人 | これまでどおりレシピや家族の機能を使いたい。なぜなら、実行環境を替えることが、使い方の変更になってほしくないから |

## 4. 要件

### 4.1 機能要件

| ID | 要件 | 応える要求 | 優先度 |
| --- | --- | --- | --- |
| FR-01 | このアプリを、Node.js 24 の系統で起動し、これまでどおり使える | R-01、R-03 | 必須 |

### 4.2 非機能要件・制約

| ID | 要件 | 観点 | 優先度 |
| --- | --- | --- | --- |
| NFR-01 | 開発、自動の確認、デプロイが指す Node.js は、いずれも 24 の系統である。20 を指定したままにしない | セキュリティ | 必須 |
| NFR-02 | 使う版は、2026-10-21 のセキュリティ更新を含む Node.js 24 である | セキュリティ | 必須 |
| NFR-03 | レシピ、家族、アカウントのできることは、この変更の前と変わらない | 互換性 | 必須 |
| NFR-04 | 足りたことの確認は、Node.js 24 でアプリが起動し、すでにある確認が通ることである。新しい自動テストの種類は足さない | 運用 | 必須 |

## 5. スコープ

| 含める | 含めない |
| --- | --- |
| Node.js の指定を 24 の系統に揃えること | 画面、保存するデータ、アカウントの機能変更 |
| 開発、自動の確認、デプロイの指定を、互いに一致させること | 設計書の新規作成 |
| Node.js 24 での起動と、すでにある確認 | Vitest（モック）、Vitest（実 DB）、e2e の新規作成 |

## 6. 前提・決定済み

| 項目 | 内容 | 出典 |
| --- | --- | --- |
| 系統 | Node.js 24 にする。22 は採らない | 2026-10-24 に、このチャットでユーザーが選択 |
| 進め方 | 要件定義のあと実装へ進む。設計は作らない | [#46](https://github.com/TOMON-9912/cooking-recipe/issues/46)。2026-10-24 にユーザーが決定 |
| 確認の範囲 | 実装時の確認は動作確認とする。3 種のテストを新たに作ることは、この開発対象に含めない | [#46](https://github.com/TOMON-9912/cooking-recipe/issues/46)。2026-10-24 にユーザーが決定 |
| 更新の事実 | 2026-10-21 のセキュリティ更新は、Node.js 22.23.4、24.22.1、26.12.1 で提供されている。20 には提供されない | [Node.js のセキュリティリリース](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) |

## 7. 受け入れ条件

- [ ] 開発、自動の確認、デプロイの Node.js の指定が、いずれも 24 の系統である
- [ ] その指定が、2026-10-21 のセキュリティ更新を含む版を使える
- [ ] Node.js 24 でアプリが起動し、すでにある確認が通る
- [ ] レシピ、家族、アカウントのできることは、この変更の前と変わらない

## 8. 未決・リスク

| 項目 | 現状 | 決めるまで実装に持ち込まないこと |
| --- | --- | --- |
| なし | 系統、進め方、確認の範囲は決まっている | — |
| 既存の道具が Node.js 24 で動かない | いまの指定は 20 である。24 で止まっても、機能の追加では解消しない | 動かない道具が出たら、バージョンを 22 に戻すか、その道具だけを直すかを、その時点で人間が決める |

## 9. 設計への申し送り

この開発対象では設計を作らない。実装では、Node.js 24 の系統に指定を揃え、その版で起動と既存の確認を行う。

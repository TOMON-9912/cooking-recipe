# 待ち時間のローディングスピナー（要件定義）

| この文書が答える問い | 待ち時間に、何を出せば、いま処理していると分かるか |

## 1. 背景と課題

- ページを開くまでのあいだ、画面が止まったように見える
- ボタンを押したあと、処理が終わるまで、押したかどうかが分からない
- いまの画面には、待ち時間であることを示すものがない

## 2. なぜ作るか

- **目的:** ページを開くまでの待ち時間と、ボタンを押したあとの処理中に、ローディングスピナーを出して、いま処理していると分かるようにする
- **価値:** 同じ操作を重ねて押したり、失敗したと勘違いしたりしにくくなる
- **成功の姿:** 待っているあいだはスピナーが見え、処理が終わるとスピナーが消えて、結果の画面になっている

## 3. 利用者と要求

| ID | 利用者 | 要求（〜したい。なぜなら〜） |
| --- | --- | --- |
| R-01 | レシピを書く人、家族で使う人 | ページを開くまでのあいだ、処理中だと知りたい。なぜなら、止まったのか開いているのか分からないから |
| R-02 | レシピを書く人、家族で使う人 | ボタンを押したあと、処理が終わるまで処理中だと知りたい。なぜなら、押したかどうかが分からず、もう一度押したくなるから |
| R-03 | レシピを書く人、家族で使う人 | 処理が終わったら、待ちの表示が消えて結果を見たい。なぜなら、終わったあとも回り続けていると、まだ処理中だと思ってしまうから |

## 4. 要件

### 4.1 機能要件

| ID | 要件 | 応える要求 | 優先度 |
| --- | --- | --- | --- |
| FR-01 | ページを開くまでの待ち時間に、ローディングスピナーが見える | R-01 | 必須 |
| FR-02 | サーバへ送って結果を待つ操作では、ボタンを押したあとの処理中に、ローディングスピナーが見える | R-02 | 必須 |
| FR-03 | 待ちが終わると、ローディングスピナーが消える | R-03 | 必須 |

### 4.2 非機能要件・制約

| ID | 要件 | 観点 | 優先度 |
| --- | --- | --- | --- |
| NFR-01 | スピナーは、待ち時間であることを示すためのものである。スピナー以外の演出（中身の形だけ先に出す、進み具合をパーセントで出す）はしない | 使いやすさ | 必須 |
| NFR-02 | レシピ、家族、アカウントのできることは、この変更の前と変わらない | 互換性 | 必須 |

## 5. スコープ

| 含める | 含めない |
| --- | --- |
| ページを開くまでの待ち時間のローディングスピナー | スピナー以外の演出 |
| サーバへ送って待つ操作すべての、処理中のローディングスピナー | 待ちが長い一部のボタンだけに限ること |
| 処理が終わったあとにスピナーが消えること | 待ち時間そのものを短くする改善 |
| | 画面や保存するデータの機能変更 |

## 6. 前提・決定済み

| 項目 | 内容 | 出典 |
| --- | --- | --- |
| 出す場面 | ページを開くまでの待ち時間と、ボタンを押したあとの処理中 | 2026-11-04 に、このチャットでユーザーが説明 |
| ボタンの範囲 | サーバへ送って結果を待つ操作すべて。一部のボタンには限らない | 2026-11-04 に、このチャットでユーザーが選択 |
| 演出の種類 | ローディングスピナー。スケルトンやパーセント表示はしない | [#53](https://github.com/TOMON-9912/cooking-recipe/issues/53) |

## 7. 受け入れ条件

- [ ] ページを開くまでの待ち時間に、ローディングスピナーが出る
- [ ] サーバへ送って待つ操作でボタンを押すと、処理中はローディングスピナーが出る
- [ ] 処理が終わると、ローディングスピナーが消える
- [ ] レシピ、家族、アカウントのできることは、この変更の前と変わらない

## 8. 未決・リスク

| 項目 | 現状 | 決めるまで設計に持ち込まないこと |
| --- | --- | --- |
| なし | 出す場面、ボタンの範囲、演出の種類は決まっている | — |

## 9. 設計への申し送り

保存するデータは増えない。スピナーをページのどこに置くか、押したボタンのところに出すかは、ここでは決めない。

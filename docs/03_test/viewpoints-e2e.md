# 結合テスト（E2E）観点表

操作や機能に依存しない、結合テスト（Playwright）で見る観点の正本。操作ごとのケースは [design/](./design/README.md) に書く。この表はケースのコピー先ではない。

実行手順は [e2e-playwright.md](./e2e-playwright.md)。層の重点は [test-scope.md](./test-scope.md)。

## 使い方

1. 対象の画面またはクリティカルパスについて、下表を上から当てる
2. 該当する観点だけ、操作のテスト設計にケースとして落とす
3. その画面に無い観点は書かない
4. RLS や Cookie の穴は E2E だけでは足りない。認可の本体は [単体テスト観点表](./viewpoints-unit.md) で見る

## 観点

| ID | 大項目 | 観点 | 確認すること | 主な層 |
| --- | --- | --- | --- | --- |
| E-01 | 導線 | 未ログイン | 認証が必要な URL はログインへ送る。元のパスが分かる | e2e / proxy |
| E-02 | 導線 | 画面の主目的 | ファーストビューで、その画面の主目的と Primary が 1 つ分かる | e2e / page |
| E-03 | 導線 | 入る・出る | 設計した入口から入れ、成功・失敗の出口へ進む | e2e |
| E-04 | 導線 | 自動戻りしない | ログイン後に戻さないと決めた画面は、戻さない | e2e |
| E-05 | 状態 | 空状態 | 説明と、次の行動（CTA またはリンク）がある | e2e / page |
| E-06 | 状態 | 失敗の案内 | 失敗したとき、画面内で理由と次の行動が分かる | e2e |
| E-07 | 状態 | 成功の確認 | 成功したあと、利用者が結果を同じアプリ内で確かめられる | e2e |
| E-08 | 認証 | ゲスト | 本登録だけの操作は、ボタンを出さず案内する | e2e / page |
| E-09 | 認可 | 役割の見え方 | できない人には、その操作のフォームや Primary が出ない | e2e / page |
| E-10 | 情報 | 見せてよい範囲 | この画面で出してよい項目だけが見える | e2e |
| E-11 | 情報 | 出してはいけないもの | 他人の識別子、登録有無、メンバーやレシピなど、設計で隠すものは出ない | e2e |
| E-12 | 操作 | クリティカルパス | 利用者の大筋（入力 → 実行 → 確認）が画面をまたいで通る | e2e |
| E-13 | 操作 | 補助アクション | Secondary（取り消し、戻るなど）が、主目的を奪わず動く | e2e |
| E-14 | 互換 | 既存画面 | 新しい画面を足しても、既存の作成・一覧・編集などの大筋が残る | e2e |

## 対象外（この表では見ない）

- バリデーションの全パターン、失敗コードの網羅 → [単体テスト観点表](./viewpoints-unit.md)
- RLS ポリシー単体、RPC 引数、snake_case 変換
- 同時実行、期限ちょうどの境界（時計を止める必要があるもの）
- ビジュアルリグレッション、全ブレークポイントの見た目

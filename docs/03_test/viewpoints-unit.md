# 単体テスト観点表

操作や機能に依存しない、単体テスト（Vitest）で見る観点の正本。操作ごとのケースは [design/](./design/README.md) に書く。この表はケースのコピー先ではない。

実行の置き場と層の重点は [strategy.md](./strategy.md)、[test-scope.md](./test-scope.md)。

## 使い方

1. 対象の操作について、下表を上から当てる
2. 該当する観点だけ、操作のテスト設計にケースとして落とす
3. その操作に無い観点は書かない（空行で埋めない）
4. 完成したテストコードは、ここにも操作ファイルにも書かない

## 観点

| ID | 大項目 | 観点 | 確認すること | 主な層 |
| --- | --- | --- | --- | --- |
| U-01 | 入力 | 必須・形式 | 空、欠落、型・形式の不正を拒否する | usecase |
| U-02 | 入力 | 正規化 | trim、大小文字など、比較・保存の前に揃える値がある | usecase / infrastructure |
| U-03 | 正常 | 1 件の成立 | 事前条件を満たすと、事後条件どおり 1 件（または 1 回）成立する | usecase |
| U-04 | 正常 | 関連の残し方 | 本体と関連が、設計どおり一緒に残る（または一緒に残らない） | usecase / infrastructure |
| U-05 | 異常 | 失敗の意味 | 利用者に理由を分ける失敗は、コードまたは意味が分かれて返る | usecase |
| U-06 | 異常 | 推測させない失敗 | 他人の資源の有無など、分けてはいけない失敗は同じ結果になる | usecase |
| U-07 | 異常 | 副作用が残らない | 拒否したとき、途中まで書いた行や中途半端な状態が残らない | usecase / infrastructure |
| U-08 | 境界 | 上限・期限・回数 | ちょうど境界の内側は通り、外側は拒否する | usecase |
| U-09 | 認証 | 未ログイン | 認証が必要な操作は、セッション無しで拒否する | action |
| U-10 | 認可 | 本人以外 | 他人の資源は読めない・変えられない | usecase / RLS |
| U-11 | 認可 | 役割 | オーナーだけ、作者だけ、など役割で分かれる操作は、足りない役割で拒否する | usecase |
| U-12 | 認可 | ゲスト | 本登録だけの操作は、ゲストを拒否する。判定は UI だけに置かない | usecase |
| U-13 | 状態 | 前提の有無 | 既にある／無い、使用済み、期限切れなど、状態ごとの可否 | usecase |
| U-14 | 状態 | 再実行 | 同じ操作をもう一度したときの結果（冪等、重複拒否、トグルなど） | usecase |
| U-15 | 永続化 | 問い合わせの形 | 渡す引数、RPC 名、snake_case 変換が契約どおり | infrastructure |
| U-16 | 永続化 | 直接アクセス | クライアントからの直 INSERT / UPDATE / SELECT が、ポリシーどおり拒まれる | RLS |
| U-17 | アプリ | 入力の変換 | フォームやパスから usecase 入力へ、欠落なく変換する | action |
| U-18 | アプリ | エラー整形 | 失敗の意味が、画面向けの結果（フィールドまたは全体）になる | action |
| U-19 | アプリ | キャッシュ | 成功後に `revalidate` するなど、設計した更新がある | action |
| U-20 | 互換 | 既存操作 | 新しい操作を足しても、既存の usecase の契約が変わらない | usecase |

# ADR 015: 実装開始条件のチェックリストをやめる

## 背景

[ADR 010](./010-issue-centered-dev-flow.md) は、実装の前に Issue のチェックリストと、チャットでの承認を置いた。[ADR 012](./012-requirements-before-design.md) と [ADR 013](./013-issue-per-process.md) で、その項目は要件定義の確定まで増えた。

個人開発では、要件定義か設計の Issue が閉じたあとに、同じ内容を実装 Issue へ転記してチェックし、チャットでもう一度承認するのが重かった。2026-11-15 の Node.js の版上げでは、要件定義の PR がマージされたあとも、実装そのものより開始条件の操作が先に来た。

## 決定内容

**実装を始める条件は、前のプロセスの Issue が閉じていることだけにする。実装開始条件のチェックリストと、チャットでの追加の承認は置かない。**

- 設計 Issue があるときは、その設計 Issue が閉じている
- 設計を作らないと決まっていて、設計 Issue が無いときは、要件定義 Issue が閉じている
- どちらも閉じていなければ実装しない。必要な設計が無いときは `/design` へ戻す
- AI は Issue を閉じない。完了のチェックも付けない

## なぜこの案か

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 閉じた要件定義 Issue か、閉じた設計 Issue だけを開始条件にする | 採用 | 個人開発では、前のプロセスが終わった事実で足りる。同じ確認をチェックリストとチャットに重ねない |
| 実装開始条件のチェックリストとチャット承認を残す | 不採用 | 前の Issue が閉じていることと二重で、実装の前に操作が増える |
| Issue を閉じる前でも、チャットの依頼だけで実装する | 不採用 | 何が終わっているかが次のセッションに残らない |

## 結果・利点

- 要件定義か設計が終わっていれば、実装に入れる
- 実装 Issue は、操作の目的・範囲・完了条件・実装計画を持つ。開始のチェックリストは持たない

## 考慮点・トレードオフ

- 前の Issue を人間が閉じるまで、実装は始まらない。閉じ忘れは、チェックリストが未記入のときと同じように止まる
- 設計 Issue が開いているのに、閉じた要件定義だけで実装しない。設計を作らないと決まっているときだけ、要件定義 Issue の完了で足りる

# 改善候補の採用基準

採否は人間が行う。AI は推奨理由を並べてよいが、結果を書かない。

発生回数は **参考** である。N 回起きたから Rule 化する、という決め方はしない。

## 見るもの

1. **再発防止できるか** — 次の同種作業で、同じずれを避けられるか
2. **一般化できるか** — 今回のファイル固有の話ではないか
3. **プロダクト固有の事実ではないか** — 事実なら Documentation。Rule にしない
4. **既に docs 01〜09 にないか** — あるなら参照を Skill に足すだけで足りることが多い
5. **Skill の参照不足ではないか** — 手順が無いだけなら Skill。常時 Rule にしない
6. **次回の判断が変わるか** — 書いても AI の行動が変わらないなら Adopt しない
7. **alwaysApply のコストは妥当か** — Rule 化は毎ターン読む。短い不変条件だけ
8. **既存 Rule と重複・矛盾しないか**
9. **ハーネスが複雑にならないか** — 新しい Skill / Rule を増やすより、既存の 1 箇所を直す

## 結果の使い方

| 結果 | 意味 |
| --- | --- |
| Adopt | Target の 1 箇所を更新し、候補に Decision を書く |
| Defer | 今は変えない。理由と、いつ見直すかを Decision に残す |
| Reject | 残さない。理由だけ残す（ファイルは消さず Status を更新） |

Target が `Judgment` なら、Adopt しても Rule / Skill / docs は更新しない。Decision に「今回限り」と書く。
